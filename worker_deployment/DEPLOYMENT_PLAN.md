# Регламент развертывания гибридной системы транскрибации (CRM + Mac Worker)

Данный документ содержит техническое описание архитектуры, требования и пошаговое руководство по развертыванию гибридной системы обработки голосовых заметок. Гибридная схема сочетает локальные вычислительные мощности (Mac Worker) для бесплатной оффлайн-транскрибации и облачные API (OpenRouter) для постобработки и резервного копирования.

---

## 1. Архитектура гибридной системы

Гибридная модель оптимизирует затраты на инфраструктуру за счет распределения задач:
1. **Локальный уровень (Mac Worker):** Выполняет энергоемкую задачу распознавания речи (ASR) с помощью локально запущенной модели WhisperX, оптимизированной под Apple Silicon GPU (Metal).
2. **Облачный уровень (CRM на VPS/Cloud Run):** Выступает в роли координатора задач (оркестратора), принимает аудиофайлы, управляет очередью FIFO, распределяет задачи по зарегистрированным воркерам и осуществляет финальный перевод/анализ через OpenRouter API.

### Схема взаимодействия (Sequence)
1. **Поступление задачи:** Пользователь отправляет аудио через Telegram Bot в CRM. CRM создает задачу со статусом `pending` / `available`.
2. **Опрос очереди (Polling):** Локальный Mac Worker отправляет периодические POST-запросы на `/api/worker/poll`.
3. **Получение и транскрибация:** При наличии задачи CRM переводит ее в статус `transcribing`, подписывает временную ссылку на скачивание аудио и отдает воркеру. Воркер скачивает файл, выполняет WhisperX-транскрибацию и возвращает сырой текст с таймкодами через `/api/worker/result`.
4. **AI-постобработка:** CRM принимает сырой текст и запускает конвейер обработки (AI Pipeline) через OpenRouter для очистки текста, генерации суммаризации и перевода (EN/TH).

## 2. Системные требования для Mac Worker

Локальный узел должен отвечать следующим характеристикам для обеспечения достаточной производительности:

* **Аппаратное обеспечение:**
  * Процессор: Apple Silicon (M1, M2, M3, M4 любой модификации: Base, Pro, Max, Ultra).
  * Оперативная память (RAM): Не менее 16 ГБ (рекомендуется для моделей WhisperX уровня `large-v3` или `medium`).
  * Свободное место на диске: Не менее 10 ГБ для кэширования моделей PyTorch/HuggingFace.
* **Программное обеспечение:**
  * Операционная система: macOS 14.0 (Sonoma) или новее.
  * Интерпретатор: Python 3.10 или 3.11 (версия 3.12+ может иметь проблемы с совместимостью некоторых библиотек глубокого обучения).
  * Системные утилиты: Homebrew, FFmpeg (с поддержкой необходимых аудиокодеков).

## 3. Подготовка окружения на стороне macOS

Выполните следующие команды в терминале macOS для настройки среды выполнения:

### Шаг 1: Установка системных зависимостей
```bash
# Установка Homebrew (если не установлен)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Установка FFmpeg
brew install ffmpeg

# Установка Python 3.10
brew install python@3.10
```

### Шаг 2: Клонирование и инициализация окружения воркера
Перейдите в директорию воркера и создайте изолированное виртуальное окружение Python:
```bash
cd mac_worker
/opt/homebrew/bin/python3.10 -m venv venv
source venv/bin/activate
```

### Шаг 3: Установка библиотек машинного обучения
Для корректного задействования GPU Apple Silicon (через бэкенд MPS - Metal Performance Shaders) необходимо установить совместимые версии PyTorch и WhisperX:
```bash
# Установка PyTorch с поддержкой MPS
pip install --pre torch torchvision torchaudio --extra-index-url https://download.pytorch.org/whl/nightly/cpu

# Установка WhisperX напрямую из репозитория для поддержки последних оптимизаций
pip install git+https://github.com/m-bain/whisperX.git

# Установка зависимостей API-клиента
pip install fastapi uvicorn requests python-dotenv ctranslate2
```

## 4. Конфигурация Mac Worker

В корневой папке `mac_worker/` создайте конфигурационный файл `.env`:

```env
PORT=8000
WORKER_INTERNAL_SECRET=secret-worker-token-2026
CRM_BACKEND_URL=https://your-crm-domain.run.app
DEVICE_TOKEN=tok-mac-m3-pro-1002
ASSISTANT_ID=usr-1002
```

Параметры:
* `PORT` — Локальный порт для запуска веб-интерфейса воркера.
* `WORKER_INTERNAL_SECRET` — Ключ авторизации, совпадающий с установленным на сервере CRM.
* `CRM_BACKEND_URL` — Полный URL-адрес вашей запущенной CRM.
* `DEVICE_TOKEN` — Уникальный идентификатор устройства (например, генерируется при первичной привязке).
* `ASSISTANT_ID` — Идентификатор ассистента, за которым закреплено данное устройство.

## 5. Настройка сетевой связанности

Так как Mac Worker работает за пределами серверного контура (например, на домашнем или офисном компьютере ассистента), необходимо обеспечить безопасное прохождение трафика.

### Вариант А: Использование Cloudflare Tunnel (Рекомендуется)
Позволяет предоставить защищенный доступ к локальному порту воркера без открытия портов на роутере и без публичного IP-адреса.

1. Установите Cloudflare daemon на Mac:
   ```bash
   brew install cloudflare/cloudflare/cloudflared
   ```
2. Авторизуйтесь в Cloudflare:
   ```bash
   cloudflared tunnel login
   ```
3. Создайте и запустите туннель для локального порта воркера:
   ```bash
   cloudflared tunnel --url http://localhost:8000
   ```
4. Полученный домен вида `*.trycloudflare.com` пропишите в CRM в качестве адреса воркера ассистента.

### Вариант Б: Использование ngrok (Альтернатива)
```bash
brew install ngrok/ngrok/ngrok
ngrok http 8000
```

## 6. Восстановление функционала на сервере CRM

Для перевода системы из полностью облачного режима в гибридный необходимо произвести следующие изменения в исходном коде сервера (`server.ts`):

1. **Реактивация конфигурационного эндпоинта:**
   Вернуть оригинальную логику отдачи конфигураций в `app.get('/api/worker/config')`, проверяющую заголовок `x-worker-secret`.

2. **Включение механизмов Heartbeat и Polling:**
   * Включить обработку активности воркеров в эндпоинте `/api/worker/heartbeat` для обновления времени последней связи (`last_heartbeat`) и статуса устройства в базе данных.
   * Раскомментировать логику в `/api/worker/poll`, которая ищет задачи со статусом `assigned` или `macbook_pending`, генерирует подписанную ссылку (`generateSignedAudioUrl`) и передает задачу воркеру.

3. **Обработка результатов транскрибации:**
   Восстановить эндпоинт `/api/worker/result`, принимающий сегментированный текст WhisperX от воркера и запускающий конвейер очистки/перевода на базе сохраненных транскрипций.

4. **Активация элементов интерфейса:**
   В панели администрирования (`SystemAiAdminControl.tsx` и `TelegramSimulator.tsx`) вернуть отображение статусов MacBook-слотов, карточек активности локальных устройств и управление лимитами распределения задач.

## 7. Мониторинг и диагностика

* **Логирование воркера:**
  Логи выполнения транскрибации и взаимодействия с API CRM выводятся в стандартный поток вывода терминала, где запущен `worker.py`. Для ведения лог-файла используйте перенаправление потока:
  ```bash
  python worker.py > worker.log 2>&1 &
  ```
* **Диагностика GPU (Metal):**
  Убедиться, что PyTorch видит графический ускоритель Apple Silicon, можно запустив интерактивный скрипт Python:
  ```python
  import torch
  print("MPS Available:", torch.backends.mps.is_available())
  print("MPS Built:", torch.backends.mps.is_built())
  ```
  При корректной настройке оба параметра должны вернуть `True`. Это гарантирует десятикратное ускорение процесса распознавания аудиофайлов по сравнению с обработкой на CPU.
